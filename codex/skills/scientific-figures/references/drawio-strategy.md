# Editable Draw.io Strategy

Use draw.io when the figure is primarily a relational or explanatory schematic and future object-level editing matters. Draft the visual argument first: name the entities, transformations, inputs, outputs, feedback paths, and connector semantics. Preserve useful composition from the accepted baseline and choose which relationships deserve emphasis before adding boxes. Then create a compact XML model with stable cell IDs, explicit parents, geometry, styles, labels, and edges. Keep ordinary labels editable; for mathematics preserve the source expression and use supported mathematical typesetting or a reproducible vector asset rather than improvised Unicode notation. Group the mathematics with its semantic node for local edits. Use supplied vector assets only when their license and source are clear.

Preview the XML through a short local browser URL or a local preview page that loads the XML into diagrams.net. This avoids oversized encoded URLs and makes the rendered canvas observable. Inspect the screenshot at the intended publication size for overlap, clipping, route direction, fan-in/fan-out, feedback loops, label hierarchy, whitespace, and style drift. If the figure is based on a reference image, compare the rendered semantics and layout to the reference without embedding the reference as a substitute for editable content.

Run structural and semantic validation before handoff: parse the XML, check unique IDs and valid parent/edge references, ensure geometry is finite and on-page, flag accidental external or oversized raster payloads, and verify that each required relationship has the intended arrow direction. Inspect the exported PDF as well as the editor: mathematics, wrapping, label spacing, and arrowheads can change at export. A valid file still needs a substantive visual judgment. Keep concise correction notes in the existing task record when useful, and verify the repaired areas on the current publication page before closing them.

This guidance follows the XML, browser-preview, and validation approach described by the MIT-licensed [drawio-diagram-builder](https://github.com/Will-hxw/drawio-diagram-builder).
